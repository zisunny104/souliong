# 3D 區域編輯說明書
<!-- site:content -->

`region3d` 是用一個自訂模型取代某個範圍內公用 3D 建物的工具。存檔之後那個範圍內的公用建物擠出永遠不會再畫出來，訪客在 3D 模式下看到的會是管理者上傳的那個模型。

## 這支工具在做什麼

3D 模式的公用建物是跟著 OpenStreetMap 的資料自動擠出的白模（或依 OSM 屬性上色的模型，見「OSM 驅動 3D」）。遇到想放精緻模型的地標（例如某棟有特色的建築、一座雕像），公用的擠出模型不夠用，這支工具讓管理者畫出一塊範圍、把那個範圍內的公用建物排除掉，改放自己上傳的 `.glb` 模型。

排除跟放模型是綁在一起的同一個動作——不能只排除不放模型，也不能只放模型不排除（那樣會變成模型跟公用建物疊在一起）。

## 步驟一：專案與區域 id

**區域 id** 只能用小寫英數字、底線、連字號，它同時是伺服器上的資料夾名稱。跟既有區域同名時，存檔前要勾選「覆蓋同 id 的既有區域」才會繼續——這是避免同名區域被默默蓋掉的確認機制，id 本身在存檔前就看得出來，不用等匯入 ZIP 才知道撞名。

**顯示名稱**是給管理者自己看的標籤，不影響訪客端顯示。

## 步驟二：畫出要排除公用建物的範圍

按「開始畫多邊形」後在地圖上依序點出範圍的每個角，至少三點，按「完成多邊形」收尾；畫錯就按「清除重畫」整個重來。

這個多邊形**同時決定兩件事**：公開端排除哪些公用建物（下面「排除清單怎麼算」會說明），以及伺服器端儲存的範圍資料本身——兩者是同一份多邊形，不是分開畫兩次。

**放置模型錨點**：模型要放在地圖上的哪個位置，按鈕點一下地圖上的位置，之後也能直接拖曳圖釘微調。錨點不一定要在多邊形正中央——模型本身的尺寸、朝向、基準點是模型檔自己決定的，錨點只是「模型的原點落在地圖上哪裡」。

**水平旋轉角度／縮放倍率／高度偏移**：模型上傳時的朝向、大小、海拔不一定剛好符合需求，這三個參數在不重新上傳模型的前提下做微調。

## 步驟三：模型檔案與存檔

**只接受 glTF 二進位格式（`.glb`）**，伺服器端會驗證檔案開頭的魔數，不是副檔名就信任。大小上限由伺服器設定決定（預設 24 MB）。

**重新編輯既有區域時，不選新檔案就會沿用目前已存的模型**，只更新多邊形與其他參數——這跟圖層的「表單沒送的欄位原樣寫回去」是同一個精神：改個角度不該逼人重新上傳一次模型。

**出處**：顯示在地圖角落的模型來源文字，例如作者、授權方式。

按下「儲存」後，瀏覽器會先把目前畫面上的多邊形範圍內的公用建物查出來（下一節說明），再把多邊形、排除清單、模型參數一次送出存檔。

## 排除清單怎麼算

這是這支工具最容易誤解的地方：**排除清單是按下「儲存」的那一刻算好、寫進去的固定清單，不是訪客瀏覽時即時重新計算的**。

存檔當下，瀏覽器裡的地圖已經載入了跟訪客端完全相同的建物圖磚，程式對照剛剛畫的多邊形，把落在裡面的每一棟建物的 id 抓出來，連同多邊形一起送給伺服器寫進 `region.json`。訪客端只是把所有已存區域的這份清單合併起來，套成一條固定的篩選規則——不管訪客怎麼平移地圖，都是同一份清單在生效。

這樣做的理由：建物的實際幾何形狀在伺服器端的 PHP 完全拿不到（那是地圖圖磚服務商那邊的向量資料），伺服器只能驗證格式、沒辦法自己算「這個多邊形框住了哪些建物」，這一步天生只能在瀏覽器裡、在地圖已經畫出來的當下做。

**代價**：如果地圖服務商那邊的建物資料更新、換了內部編號，舊的排除清單可能會對不上，公用建物有機會重新冒出來、跟自訂模型疊在一起。存檔或重新掃描時，如果有建物查不到可用的 id，畫面上會當場提示「有幾棟建物沒有可用的 id、目前無法排除」——這不會擋下存檔，是留給管理者自己判斷要不要先處理。

## 重新掃描

既有區域的畫面上會多一顆「重新掃描排除清單」按鈕。按下去**只會重新查一次目前多邊形框住的建物、覆寫排除清單**，多邊形本身與已上傳的模型都不會變。

這是排除清單失效時的補救辦法：不用重新整個走一次「畫多邊形＋上傳模型」的流程，只要在同一個區域裡按一次重新掃描，就能用目前的建物資料重新算一份清單。

**限制**：重新掃描終究還是靠瀏覽器裡的地圖查詢，如果某些建物在目前的圖磚裡根本查不到（不只是編號換了，而是這棟建物本身在地圖服務商那邊已經找不到對應資料），重新掃描也救不回來，只能回到步驟二重新畫一次範圍確認。

## 刪除區域

既有區域的畫面上，存檔按鈕旁會多一顆「刪除這個區域」按鈕（紅色，跟存檔／重新掃描區隔開來）。按下去會先跳出確認視窗，說明排除清單會失效、公用建物會重新畫出來——這個動作不可逆，資料夾與裡面的模型檔都會整個刪掉。刪除成功後會導回後台「工具」分頁。

## 備份與搬遷

每個區域都可以匯出成一個 ZIP（內含 `region.json` 與模型檔），用來手動備份或搬到另一台伺服器。匯出按鈕在專案卡片「地圖圖層」對話框的 3D 區域清單裡，每一列旁邊的下載圖示。

匯入時選擇一個先前匯出的 ZIP 上傳：ZIP 裡的區域 id 如果跟現有的撞名，預設會擋下來並列出撞到的 id，要先勾選「覆蓋同名 3D 區域」再重新上傳才會覆蓋；沒撞名的話直接落地。

## 切完之後

工具本身只負責把區域資料放到正確的資料夾，**不會**自動改動任何一張地圖的其他設定。3D 模式本身要先在該地圖開啟，才看得到這個區域的效果。
