# 管理權限來源

身分管理顯示兩種來源：

- 全站管理者：繼承所有專案的管理權限，不受專案管理功能開關影響。
- 專案管理者：專案帳號與管理 PIN 依各自授權使用；關閉專案管理功能後，這些專案授權不生效。

全站管理者名單與專案帳號名單僅提供全站管理者查看。其他管理者只會看到全站管理權限的來源說明，不會取得全站帳號名稱。

具有「授權管理」權限的專案管理者，可看到權限完全包含在自己權限範圍內的管理 PIN。比較的是實際權限集合，不是權限數量；包含未識別的已啟用權限也不會公開。將既有 PIN 轉成帳號的請求使用相同限制，不能透過直接送出請求繞過名單限制。

驗證：`PLAYWRIGHT_PATH=/path/to/playwright node tools/identitysourcecheck.js`。測試建立並清除獨立暫存專案，檢查全站名單保密、權限子集、互不包含的權限、未知權限、轉換請求，以及 390／1280 像素寬度的來源卡片。

## den 單一登入

登入頁除了主 PIN、帳號與專案 PIN，另有「使用 den 登入」，用 toka 的 den 後台確認身分，原本的方式都保留。

- 超級使用者解析成全站管理者，等同主 PIN。
- 一般使用者要有 `souliong` 身分組才放行。第一次登入出現選擇頁，可輸入原帳號與密碼綁定現有帳號，或建立不需密碼的新帳號。一個 den 身分只綁一個帳號，一個帳號也只綁一個 den 身分，後台可解除綁定，沒有密碼的帳號不能解除。
- den 撤銷身分後，用 den 登入的全站管理者最多 5 分鐘後登出，den 連不上時不登出。綁定的本機帳號不受影響，只是不能再用 den 登入，已有的帳號登入與密碼登入照常。
- 設定在 `api/config.php` 的 `den_sso`，範例見 `api/config.example.php`。子站金鑰檔不存在時整段關閉，登入頁不顯示按鈕。

驗證：`php tools/checkall.php`，den 登入流程需要實際的 den 後台，用本機模擬端點測試。
